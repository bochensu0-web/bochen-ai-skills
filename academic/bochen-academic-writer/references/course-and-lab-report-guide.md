撰写或修改大学日常实验报告、上机报告、课程综述、通识课论文及英文摘要时按需读取本文件。

## 1. 理工科专业课实验/上机报告高分结构（告别“贴图流水账”）

许多同学实验做得很辛苦，报告却只拿良/中，原因往往是“前 3 页抄指导书原理 + 中间贴 5 页无注释长代码 + 最后放一张运行成功黑框图写一句‘通过本次实验我学会了……’”。推荐高分结构：

1. **实验环境与关键配置（3–5 行表格或短列表）**：OS、编译器/Python 版本、硬件（CPU/GPU）、数据集规模或测试样例说明（体现可复现性）。
2. **核心思路与关键数据结构/模块设计（1 页内）**：画一张简明流程图或状态转换图，只贴**最核心的 15–30 行算法/接口代码片段**并配关键决策注释（完整源码放附件，不拿几百行 `import` 和样板代码凑页数）。
3. **测试验证与边界实验（核心得分点）**：
   - 正常样例 + 边界/异常样例（如空输入、并发冲突、极端参数、噪声样本）对比表；
   - 每张图/表下方必须紧跟 3–5 句文字解读：**观测到了什么数值趋势 → 为什么符合（或偏离）理论复杂度/模型假设**。
4. **实验排障记录与误差分析（最能体现独立完成！）**：如实记录实验过程中踩过的 1–2 个真实问题（例如“初始学习率设 `1e-2` 导致 Loss NaN，排查发现未加梯度裁剪且未归一化输入，改为 `3e-4` 后第 8 轮稳定收敛”）。
5. **实验总结与思考题**：直接回答指导书思考题的机制原因，删除“锻炼了动手能力、受益匪浅”等套话。

## 2. 课程论文与综述常见“低分水词”替换对照

| 低质量空泛写法 | 高信息量具体改法 |
| --- | --- |
| “随着互联网和人工智能技术的飞速发展，XX 越来越受到广泛关注。” | 直接点出具体场景矛盾：“在 `[具体场景]` 中，当 `[数据规模/实时性/噪声条件]` 变化时，传统 `[基线方法]` 会因 `[具体机制瓶颈]` 导致准确率或吞吐下降。” |
| “文献 [1] 提出了 A，文献 [2] 提出了 B，文献 [3] 提出了 C。” | 按技术路线归类对比：“针对 `[某子问题]`，现有方案主要分为两类：以 [1,2] 为代表的 `[路线一]` 降低了计算开销，但依赖 `[强假设]`；[3] 采用的 `[路线二]` 放宽了该假设，却引入了 `[新代价]`。” |
| “由图 3 可知，本文方法效果非常好，显著优于传统方法。” | “如图 3 所示，在 `[测试集名称]` 上，该方法 Macro-F1 达到 `[具体数值]`，较 `[基线名称]` 提高 `[差值]` 个百分点；主要收益集中在样本较少的长尾类别，而在 `[某易混类别]` 上仍存在误判。” |
| “本文具有重要的理论意义和广阔的应用前景。” | 具体写清：“本实验验证了 `[具体模块]` 在纯 CPU 低资源条件下的可行性，可为 `[具体小场景]` 提供参考，但尚未在 `[更大规模/跨域场景]` 下检验泛化能力。” |

## 3. 英文摘要（Abstract）高频中式英语（Chinglish）纠偏表

| 典型中式英语硬伤 | 问题原因 | 地道学术英文改法 |
| --- | --- | --- |
| `With the rapid development of deep learning...` | 万年模板废话，零信息量 | 直接写任务与挑战：`Deploying vision classifiers on edge CPU devices remains challenging due to...` |
| `Aiming at the problem of..., this paper proposes...` | 悬垂分词（`Aiming` 逻辑主语是人不是 `paper`！） | `To address low-resource constraints, we propose...` 或 `This paper presents... to mitigate...` |
| `Using attention mechanism, the accuracy is improved.` | 悬垂分词（`accuracy` 不会自己 `use`！） | `Incorporating an attention module improves accuracy from X% to Y%.` |
| `We make an experiment on...` / `do a research` | 动宾搭配不当（`research` 不可数） | `We evaluate our method on...` / `We conduct experiments on...` |
| `prove that our model is optimal` | 实验只能支持经验结论，非数学定理证明，也不是全局最优 | `demonstrate / show that our approach outperforms the baselines on...` |
