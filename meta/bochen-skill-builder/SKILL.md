# 博晨 Skill 架构与打磨构建器

## 核心设计哲学

把 Skill 写成另一位高水平 Agent **拿到就能执行的决策协议与领域检查单**，而不是给人类看的科普宣传稿。只写会真正改变模型默认行为的判断规则、分流条件、领域硬约束与防坑清单；模型天生就会的常识一律删掉，节约宝贵的上下文窗口。

## 不适用场景

- 只用一次的临时任务指令直接写进当轮提示词，不新建独立 Skill。
- 若现有 13 个 Skill 已覆盖该领域、只是少了某类细分场景规则，**优先往对应现有 Skill 的 `references/` 模块补齐或微调其工作流**，绝不盲目拆出职责高度重叠的碎片化新 Skill。
- 严禁未经审查直接安装外部来路不明的第三方包含可执行脚本的 Skill；安装前必须先审计脚本读写范围、网络外发与凭据安全。

## 标准架构与渐进式披露规范

每个 Skill 遵循紧凑分层，兼顾 **Antigravity**（`~/.gemini/config/skills/` 或 `.agents/skills/`）、**Codex**（`~/.codex/skills/`）与 **Claude Code**（`~/.claude/skills/`）：

```text
skill-name/
├── SKILL.md              # 核心路由、硬边界、主工作流与发前自检（控制在 80–200 行，上限 500 行）
├── README.md             # 给人类阅读的简短定位、适用边界与 1 条调用示例（不复制 SKILL.md 正文）
├── agents/openai.yaml    # 客户端 UI 展示名、一句话简介与默认调用提示词（UTF-8 无乱码）
├── references/           # [可选，仅一层深度] 高密度领域规范、对照表、避坑手册，在 SKILL.md 中明确何时按需加载
├── scripts/              # [可选] 确定性只读审计、安装或打包脚本（必须附带自动化单元测试）
└── examples/             # [可选] 最小可复用输出骨架或改写前后对比
```

## 新建或打磨 Skill 的 8 步闭环

1. **真实场景收集**：先列出 4–6 条中国大学生真实会问的原话（含口语化表达与混合需求）。
2. **正交边界判定**：对照仓库 `evals/TRIGGER-MATRIX.md` 检查与相邻 Skill 的分工——写清“本 Skill 主管什么”以及“遇到哪类相邻问题立刻转交哪个 `$bochen-*`”。
3. **高区分度 `description` 编写**：客户端在未激活 Skill 前**只看得到 YAML frontmatter 的 `name` 和 `description`**！必须把核心能力、典型校园场景与用户高频触发词全部浓缩进 `description`，且文件夹名与 `name` 100% 一致。
4. **公共表达解耦**：全局中文语感、结论前置与低 AI 腔统一由 `$bochen-answer-style` 负责，各专项 Skill 只写本领域的硬核方法论，结尾一行引用 `$bochen-answer-style` 即可，不重复堆叠语言规则。
5. **诚实与安全红线内建**：学术/科研类必立“零编造文献与数据”门槛；求职/竞赛类必立“零伪造经历与指标”门槛；系统操作类必立“高危命令预警与密钥防泄漏”门槛。
6. **渐进式模块下沉**：把院校细则、OJ 平台差异表、中英误译对照表、镜像源命令集下沉到 `references/*.md`，保证简单问题不加载冗余长文。
7. **正向 + 近邻负向评测（Evals）**：在 `evals/<skill-name>.json` 中至少编写 4 条用例（含至少 1 条极易误触发的相邻领域负样本与 1 条诚信/安全边界拦截样本），同步更新 `evals/TRIGGER-MATRIX.md`。
8. **自动化校验与干净打包**：运行仓库测试套件（校验 YAML、UTF-8 无乱码、无姓名错字、全部 Markdown 相对链接可达）与 `scripts/package_skills.py`（确保生成的 `.zip` 绝不混入 `.git/` 或 `__pycache__/`）。

## 审查现有 Skill 的四把尺子

1. **删掉这一条规则后，模型回答会变差吗？** 不会变差的空泛正确的废话（如“请保持专业和全面”）立刻删掉。
2. **是否真正适配中国大学生真实处境？**（国内教材记号、PTA/CSP/四六级、大创/毕设规范、国内镜像网络、保研/秋招真实痛点）。
3. **复杂与极简输入是否都能优雅处理？**（既不把一句话问题写成长篇课程，也不在缺少实验数据时替用户瞎编）。
4. **全仓测试是否 100% 绿灯？** 每次修改后必须跑通 `tests/` 下全部自动化检查。
