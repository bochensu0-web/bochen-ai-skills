# 中国高校课程实训、组队联调与科创竞赛实战手册

在推进课程设计、综合实训多人大作业、大创项目及数学建模/科创比赛时按需读取本文件。

---

## 1. 多人实训大作业“零扯皮”接口契约模板

3–4 人小组最常见的灾难是：前两周各写各的，最后两天发现字段名、类别编码、路径与依赖版本全对不上。开工第 1 天先建一份 `docs/interface_contract.md`：

1. **统一内部枚举码**：内部逻辑一律用固定小写英文枚举（如 `recyclable / hazardous / kitchen / other`），只在前端展示层映射中文文案，禁止模块间传中文字符串再做模糊匹配。
2. **统一响应信封**：
   - 成功：`{"ok": true, "result": {...}, "service": {"mode": "model_v1"}}`
   - 失败：`{"ok": false, "error": "MODEL_UNAVAILABLE", "message": "可读中文排障提示"}`（使用稳定错误码，不把 Python 原始 Traceback 暴露给前端页面）。
3. **个人分支与提交红线**：
   - 根目录立刻建 `.gitignore` 排除 `.venv/`、`__pycache__/`、`node_modules/`、`.env`、`*.pt`、`*.db`。
   - **严禁用 GitHub 网页拖拽上传多级文件夹**（网页端上传大批量子目录极易丢失层级或覆盖同名 `README.md`/`.gitignore`），统一走本地 `git add / commit / push` 并在合并前跑通 `run_checks.py`。

## 2. 课堂现场验收 / 答辩防翻车 6 条铁律

1. **首屏 10 秒可体验**：内置 2–3 张经授权的本地示例输入（按钮“一键加载示例”），评委老师上台点一下就能走完全流程，不用现场翻文件夹找测试图/测试文本。
2. **模型预热（Warm-up）**：服务启动时预加载权重或向量库，不在老师点下第一个按钮时才卡顿 15 秒加载。
3. **断网/缺Key优雅降级**：若教室连不上外网或 API 限流，自动切入本地规则/离线引擎并在界面右上角明示当前运行模式。
4. **双保险录屏备份**：无论系统本地多稳，答辩前必须录好一段 2–3 分钟无剪辑造假的真实操作 MP4 放在桌面，万一教室投影机分辨率或电脑驱动出故障可立即切视频讲解。
5. **诚实汇报短板**：老师问“准确率为什么不是 99%”或“拍一张模糊混合图为什么分错”时，直接拿出混淆矩阵与错误样本分析（如“污染纸制品与可回收纸箱视觉特征重叠，我们设置了 `<0.60` 低置信度人工复核拦截”），这在工科实训里是**加分项**而非扣分项！
6. **清楚交代个人贡献**：组队答辩每人必须能指着架构图说清自己独立写的模块、解决的 1–2 个真实 bug 及验证测试数量。

## 3. 大创与数学建模高频评审扣分点速查

### 大创（国创 / 市创 / 校创）
- **立项被刷主因**：题目大而空（“基于大模型的智慧教育全平台”）、技术路线只有几个名词框图没有数据来源与评测指标、把商业计划书口号当成技术方案。
- **高通过率写法**：限定具体场景 + 明确开源基线与拟改进点 + 可获取的公开数据集/校内脱敏小样本 + 分季度里程碑（Q1 基线复现与数据构建 → Q2 核心改进与消融 → Q3 原型封装与结题报告）。

### 数学建模（国赛 / 美赛）
- **摘要（占印象分一半以上）**：第一段点明问题本质与总体思路；中间每段对应一问，必须写出**具体用了什么数学模型 + 什么求解算法 + 算出的核心具体数值结论**（如“最大吞吐量为 `142.6` 辆/小时，较基准方案提升 `18.4%`”），严禁写成“针对问题一，我们建立了优化模型，算出了最优解，结果见正文”的空壳摘要！
- **灵敏度分析不可少**：改变关键参数 $\pm 5\%, \pm 10\%$ 画曲线看结论是否稳健，证明模型不是靠凑某一个魔法常数才成立。
