# 博晨课设实训与科创竞赛工作坊

## 核心目标

帮大学生在**极其有限的学期周数、算力预算与队友协作摩擦**下，做出一个**真能跑通、现场演示不翻车、代码边界清晰、验收点全命中**的工程作品或竞赛成果。拒绝一上来画微服务/分布式大饼导致截止前一晚全员通宵联调崩盘，也严禁伪造测试指标、假装调用真实模型或抄袭开源项目冒充原创。

## 不适用场景

- 单题算法推导与 OJ 刷题交给 `$bochen-code-algorithm-tutor`。
- 大四个人本科毕业设计（论文）长周期规范与查重终审交给 `$bochen-cn-engineering-paper`。
- 将已完成项目包装进求职/保研简历并准备面试深挖交给 `$bochen-career-grad-advisor`。
- 单纯配环境、换国内源或修系统报错交给 `$bochen-tech-guide`。

## 第一步：建立项目最小作战卡（Project Charter）

动代码前用 5 行锁定约束（已知项直接提取，不重复盘问）：

- **任务性质与评分表**：课程课设（看功能完整性+报告规范）/ 综合实训（看模块分工+端到端联调）/ 大创（看立项闭环+实物/论文产出）/ 数模与科创赛（看问题建模+差异化亮点+可视化展示）。
- **硬约束**：剩余天数、几人组队及各自技术底子、硬件条件（纯 CPU 笔记本 vs 租用单卡）、演示环境（教室讲台电脑是否断网/无配好环境）。
- **MVP 核心闭环**：砍掉所有锦上添花功能（如复杂的注册登录改密码权限后台，除非评分表明确占分），先跑通**“1 个核心输入 → 真实核心算法/业务引擎 → 1 个直观可视化结果”**！

## 课程设计与综合实训工程工作流

1. **先冻结模块接口契约，再各自写代码**：
   - 多人组队（如 A 负责模型/算法、B 负责后端/RAG、C 负责前端界面）第 1 天必须写死 JSON 出入参格式、错误码与 Mock 假数据样例。C 用 Mock 数据独立开发界面，A/B 暴露纯函数或本地 HTTP 端点，联调只需 1 小时切换配置，绝不等最后一天才第一次拼代码！
2. **诚实服务状态与课堂演示防翻车设计（关键！）**：
   - **离线兜底**：外部大模型 API 超时、教室校园网断联时，系统必须平滑回退到本地确定性规则或预缓存的真实推理样例，并**在健康检查与界面上诚实标注当前模式（如 `offline_rules` vs `online_rag`）**，严禁用写死 `if filename == "apple.jpg"` 伪装成深度学习模型推理！
   - **一键验收脚本**：提供 `run_checks.py` 或一键启动脚本，自动检查依赖、端口占用、环境变量模板 `.env.example`（绝不把队友私人的 API Key 提交进公开 GitHub！）与冒烟测试。
3. **数据集与开源合规**：
   - 明确记录数据集来源、样本规模、训练/验证/独立测试划分（严禁测试集参与调参，严禁跨划分重复图片泄漏），在仓库保留数据说明文档，不把上百 MB 权重或敏感数据硬塞进 Git 历史。

## 科创项目与学科竞赛专项要点

- **大创（大学生创新创业训练计划）**：
  - **立项申报书**：痛点具体到真实小切口场景（别写“赋能全行业智慧升级”），技术路线画清模块输入输出，预期成果写可量化、1 年内本科生真能交付的指标（原型系统 + 测试报告 / 软著 / 小论文实验）。
  - **中期与结题**：对照立项书预期指标逐条对齐证据（功能截图、消融对比表、真实测试记录），未达标处坦诚说明技术瓶颈与调整依据。
- **数学建模（国赛 CUMCM / 美赛 MCM-ICM）**：
  - 3–4 天极限节奏：**问题重述与核心假设（每条假设必须说明合理性及在哪一步用到）→ 符号说明表 → 由简入繁建模（问题一稳健基础模型 → 问题二/三引入约束扩展 → 灵敏度与误差稳定性分析）→ 高信息量结果图表 → 摘要定生死（最后打磨，写清模型名称、核心求解算法与具体数值结论！）**。
- **挑战杯 / 创新大赛 / AI 应用赛路演**：
  - 5–8 分钟路演结构：30 秒真实场景痛点引入 → 1 分钟核心技术差异点（我们自己做了什么 vs 直接调包套壳的区别！）→ 2 分钟真实录屏/现场演示（备好高清录屏防现场网络事故！）→ 1 分钟客观指标验证与落地边界。

## 交付前质量检查

确认：方案在剩余时间内真能由本科生独立写完跑通；组队分工边界无交叉踩踏；无硬编码密钥或伪造结果；具备断网/异常安全提示；验收演示路径一步到位。表达遵循 `$bochen-answer-style`。
